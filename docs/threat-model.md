# Threat model

## Assets and trust boundaries

Assets are private target URLs, link-management permissions, password hashes, click metadata, audit history and the visitor-HMAC secret. Trust boundaries are the anonymous redirect route, authenticated OCS API, administrator settings, outbound title-fetch client, imported files, local MMDB and reverse proxy.

## Controls and residual risk

| Threat | Control | Residual risk / operation |
|---|---|---|
| XSS in title, description, tag or referrer | Vue text bindings, escaped PHP templates, no raw HTML rendering | Review any future rich-text feature separately |
| SQL injection / ReDoS | Query Builder named parameters; bounded literal filters; fixed alias regex | Database administrators remain trusted |
| CSRF | Nextcloud request tokens on mutating authenticated routes | Public password POST is exempt because no session state is mutated; it is rate-limited |
| IDOR / share escalation | Service-level `LinkPolicy`, owner-scoped mappers and explicit share validation | Admin-wide management is opt-in |
| SSRF / metadata access | Fetch disabled by default; OCP HTTP client; DNS/IP checks; every redirect revalidated; time/redirect/body caps | DNS rebinding is additionally dependent on Nextcloud HTTP-client local-address protection |
| Scheme bypass / malicious domains | `parse_url`, credential rejection, explicit scheme list, allow/block lists, revalidation on redirect | Open redirect is the product purpose; admins must maintain domain policy |
| Alias squatting / races | reserved names, exact unique hash, bounded collision retry, cryptographic random default | Custom aliases can still be socially misleading |
| Host-header poisoning | links generated by `IURLGenerator` or validated configured base URL | Reverse proxy/trusted-domain configuration remains a server responsibility |
| Password brute force | `password_hash`/`password_verify`, anonymous and user rate-limit attributes, generic failure | Distributed attacks need infrastructure-level rate limiting |
| Click/click-limit race | single conditional atomic update | 301/308 caches can bypass future counting |
| Privacy/fingerprinting | no full IP or raw UA persisted; scoped rotating HMAC; major versions only; referrer redaction | Detailed mode still creates pseudonymous behavioural data |
| Token/secret leakage | secret marked sensitive; no token query parameters; structured logs omit URL/password/token | Optional personal-token schema is dormant until a separately reviewed endpoint exists |
| CSV/XML/JSONP attacks | formula prefixing, bounded CSV/JSON only; no XML parser, JSONP or legacy endpoint | Spreadsheet users can override warnings manually |
| Import/volume abuse | authenticated rate limit, 5 MiB and 5,000-row caps, bounded pages | Large legitimate migrations should use OCC |
| Dependency compromise | lockfiles, Composer/npm audit and CI | Maintainers must review lockfile updates |

## Post-implementation review

The final design keeps anonymous functionality to lookup/access/redirect and password verification. Management, expansion, statistics, QR and import/export all require Nextcloud authentication and policy checks. Statistics are fail-open only after access and target validation, so telemetry failures cannot turn into authorisation bypasses. No secrets, real credentials, MMDB or signing keys are committed.
